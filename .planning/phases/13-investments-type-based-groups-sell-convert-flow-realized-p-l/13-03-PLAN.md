Schema decided here (Claude's Discretion, recorded):

budgeting.investment_history
id uuid PK DEFAULT gen_random_uuid()
tenant_id uuid NOT NULL
budget_id uuid NOT NULL REFERENCES tenancy.budgets(id) ON DELETE CASCADE
holding_id uuid NOT NULL REFERENCES budgeting.investments(id) ON DELETE CASCADE -- roadmap "Delete erases the holding and its history"
kind text NOT NULL CHECK (kind IN ('start','buy','add','value_change','withdraw','convert_out','convert_in'))
effective_date date NOT NULL -- user-picked (D-06); Start = created_at::date (D-09)
amount_cents bigint NULL, amount_currency char(3) NULL -- display amount: cost for start/buy/add, new value for value_change, RECEIVED for withdraw/convert_* (D-17, original ccy)
qty_delta numeric(28,8) NULL -- signed; quantity holdings only
cost_delta_cents bigint NOT NULL DEFAULT 0, cost_currency char(3) NULL -- signed change of held cost in buy ccy
flow_cents bigint NOT NULL DEFAULT 0, flow_currency char(3) NULL -- external contribution, signed, ORIGINAL ccy (D-19); 0 on value_change/convert_*
sold_cost_budget_cents bigint NULL, realized_budget_cents bigint NULL, budget_currency char(3) NULL -- frozen at effective_date (D-18), withdraw/convert_out only
value_delta_cents bigint NOT NULL DEFAULT 0 -- signed change of current value (holding ccy), amount holdings only; lets delete = full undo (D-06) subtract it back
prior_principal_cents bigint NULL, prior_start_date date NULL -- deposit sales only (D-20): principal (= cost) and deposit_start_date BEFORE the sale, restored on undo (the restart is not delta-expressible)
transfer_id uuid NULL -- both legs of a conversion share it (pairing decision: two rows, one id)
created_at timestamptz NOT NULL DEFAULT now()
deleted_at timestamptz NULL -- entry delete = soft delete; every read filters deleted_at IS NULL
Indexes: (budget_id, tenant_id, effective_date) WHERE deleted_at IS NULL; (holding_id); (transfer_id) WHERE transfer_id IS NOT NULL

Type of an entry = JOIN to the holding's CURRENT ui_type (no type column), so "Change type" (roadmap 6) carries realized with the holding and archived holdings keep contributing realized to their type.

tenancy.budgets.investment_type_order text[] NOT NULL DEFAULT '{}' -- D-12 "order saved per budget" (resolves RESEARCH A3 in favour of the locked decision: per budget, shared by members; NOT per-member ui_prefs)

New ui_type CHECK set: stocks, crypto, treasury_bond, collectibles, real_estate, other, precious_metals, cash, broker, deposit, savings, possession.
