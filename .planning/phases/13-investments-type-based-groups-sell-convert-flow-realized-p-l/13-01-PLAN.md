Contract this plan CREATES (later plans 13-07/13-08 and the web code call these; keep names exact):

sellAmountHolding(i: { buyCents: bigint; valueCents: bigint; keepCents: bigint }) => { keptCostCents: bigint; soldCostCents: bigint }

- keptCost = round_half_even(buyCents * keepCents / valueCents); soldCost = buyCents - keptCost
- throws RangeError("keep_out_of_range") when keepCents < 0 or keepCents >= valueCents ("Nothing to sell"); keep = 0 is a full sale
- throws RangeError("no_value") when valueCents <= 0

sellQuantityHolding(i: { quantity: string; buyPriceCents: bigint; sellQuantity: string }) => { newQuantity: string; soldCostCents: bigint }

- newQuantity = quantity - sellQuantity (big.js string, no trailing zeros beyond 8 dp); soldCost = round_half_even(buyPriceCents * sellQuantity)
- throws RangeError("sell_qty_out_of_range") when sellQuantity <= 0 or sellQuantity > quantity

realizedInBudget(i: { receivedCents: bigint; receivedToBudgetRate: string; soldCostCents: bigint; costToBudgetRate: string }) => { receivedBudgetCents: bigint; soldCostBudgetCents: bigint; realizedBudgetCents: bigint }

- both rates MUST be "as of the sale effective_date" (caller's job; D-18). Each side rounded once half-even, realized = received - soldCost

buyMore(i: { quantity: string; buyPriceCents: bigint; addQuantity: string; paidCents: bigint }) => { newQuantity: string; newBuyPriceCents: bigint }

- new avg unit price = round_half_even((buyPriceCents*quantity + paidCents) / (quantity + addQuantity))

addMoney(i: { buyCents: bigint; amountCents: bigint }) => { newBuyCents: bigint } // amount holdings (qty = 1)
mergeIntoAmountHolding(i: { buyCents: bigint; currentCents: bigint; receivedCents: bigint }) => { newBuyCents: bigint; newCurrentCents: bigint }

sellDepositPart(i: { principalCents: bigint; valueCents: bigint; keepCents: bigint }) => { newPrincipalCents: bigint; soldCostCents: bigint }

- D-20 (user 261025, corrected): a deposit's principal IS its cost (one column, buy_price_cents). newPrincipal = keepCents (= new cost; the caller also sets deposit_start_date = sale date, rate and cap frequency unchanged); soldCost = principalCents - keepCents. With received = value - keep, realizedInBudget gives realized = value - principal = ALL interest earned so far. soldCost may be negative when keep > principal (keep 10_200 of a 10_500 deposit with principal 10_000 -> soldCost -200); that is intended: lifetime cost (held 10_200 + sold -200 = 10_000) and total P/L (+500) stay exact. Document this in the function comment.
- throws RangeError("keep_out_of_range") when keep < 0 or keep >= value; keep 0 = sell everything (soldCost = principal)
- undo of a deposit sale is NOT delta-based (the start date restarts): the caller stores prior_principal_cents + prior_start_date on the history row and restores them (13-08)

reverseEntry(i: { shape: "quantity" | "amount"; quantity: string; buyPriceCents: bigint; currentPriceCents: bigint | null; qtyDelta: string | null; costDeltaCents: bigint; valueDeltaCents: bigint }) => { quantity: string; buyPriceCents: bigint; currentPriceCents: bigint | null }

- D-06 full undo. REVERSAL RULE (stated once, used everywhere): an entry is undone by subtracting ITS OWN stored deltas from the holding's CURRENT state — never by restoring a snapshot. So if the holding changed after the entry (a later sale, a later add), those later changes survive and only this entry's effect is removed. Every history row stores qty_delta, cost_delta_cents (held cost, buy ccy) and value_delta_cents (current value change, holding ccy; amount holdings only) for this purpose (column added in 13-03).
- amount shape (qty 1): buy = buyPriceCents - costDeltaCents; current = currentPriceCents - valueDeltaCents; quantity unchanged
- quantity shape: newQty = quantity - qtyDelta; total cost = buyPriceCents*quantity - costDeltaCents; buy (per unit) = round_half_even(total / newQty); current price unchanged
- throws RangeError("would_empty_holding") when a quantity holding's newQty <= 0 (caller decides: delete a conversion-created destination, else 422)
- throws RangeError("would_go_negative") when the resulting buy/current/total cost < 0
