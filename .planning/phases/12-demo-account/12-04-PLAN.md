<objective>
Build the prospect-facing surface: the `/demo` entry point, the first-paint dialog with a language picker, and the persistent demo banner.

Purpose: everything before this plan makes the demo safe; this plan makes it findable and comprehensible. The one non-obvious constraint is that the account is SHARED — so anything a visitor chooses must live in their browser, never on the user row, or visitor B inherits visitor A's settings.
Output: `/[locale]/demo`, the dialog, the banner, EN/PL/UK strings, component tests and a Gherkin E2E feature.
</objective>

INTERFACES — exact analogs; use directly.

Locale switching already exists — reuse, do not reimplement: `apps/web/src/components/settings/locale-select.tsx`, `apps/web/src/middleware.ts`, `apps/web/src/lib/negotiate-locale.ts`. Project memory records that the settings locale change is a hard-reload locale swap; the dialog may soft-nav instead, but verify the swap actually takes effect rather than assuming.

Per-browser state (the shared-account constraint):

- locale → the existing locale cookie (already what middleware reads).
- "dialog seen" → `localStorage`. Guard reads/writes in try/catch — a private window or blocked site data must still render the page.
- Neither may call any endpoint that persists to the demo user row.

Dialog + banner styling: DESIGN.md is the authority (Binance dark canvas, single yellow accent used scarcely, flat blocks, no gradients/glass). The banner is informational, not alarmist — PRODUCT.md's "calm under stress" register. Do not spend the yellow accent on the banner; it is not a CTA.

Radix dialog note (project memory): `onCloseAutoFocus` needs `preventDefault()` or the close-refocus trips `:focus-visible` rings.

i18n: `apps/web/messages/{en,pl,uk}.json`. All three, no exceptions — a missing key ships as a raw key string.

E2E conventions (project memory, non-negotiable): `.feature` + Page Objects, never a raw `.spec.ts`. Config source is `apps/web/playwright.config.ts`; base URL is `https://budget-dev.madonzy.com`, never localhost. Waits must be bounded — an unbounded `dispatchEvent` wait consumes the whole test timeout and any `.catch()` never runs.

Web rebuild (project memory, causes more false "it didn't work" than anything else): `apps/web/**` edits do NOT hot-reload — `docker compose build web && make restart-web`, and verify the SERVED bundle, since the build cache can ship a stale image.
