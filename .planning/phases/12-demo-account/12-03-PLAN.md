<objective>
Prove and enforce the two properties the demo's safety rests on: the demo account cannot read the owner's data, and it cannot damage the shared login or reach a real person.

Purpose: SC5 is the user's stated hard requirement ("make sure that demo account will never be able to access my data"). It is already true by construction — the demo user's `budget_members` rows point only at demo budgets, and RLS derives `app.tenant_ids` from membership — so this plan's job is to PIN it in CI, not to add a new mechanism. Adding a second mechanism would create a second thing that can be wrong.
Output: a tenant-leak gate test, the `demoGuard` middleware, and tenant-scoped suppression in the outbox and push dispatchers.
</objective>
