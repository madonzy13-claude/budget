<interfaces>
New contracts (this plan defines them; plans 12/13 consume them):

convertCents(cents: bigint, rate: string): bigint — Big(cents.toString()).times(rate).round(0, Big.roundHalfUp) → BigInt. Never relies on global Big.RM (money.ts sets RM=2 half-even globally).

type ReserveSettlementLine = { currency: string; cents: bigint /* > 0 */; direction: "TOPUP" | "WITHDRAW"; equiv?: { currency: string /* budget ccy */; cents: bigint } };
type ReserveSettlement = { netBudgetCents: bigint /* signed, budget ccy: >0 surplus, <0 shortfall */; direction: "TOPUP" | "WITHDRAW" | null; lines: ReserveSettlementLine[]; unconvertible: string[] };

settleReserveByCurrency(input: {
  needByCurrency: Map<string, bigint>;      // Σ category reserve R per category currency
  walletsByCurrency: Map<string, bigint>;   // Σ RESERVE wallet balance per wallet currency
  reserveWalletCurrencies: Set<string>;     // currencies that HAVE a RESERVE wallet (even at 0 balance)
  budgetCurrency: string;
  rate: (from: string, to: string) => string | null; // today's rate; null = no rate
}): ReserveSettlement
</interfaces>

Algorithm (fixed here so tests and code agree):
1. For each currency c in need ∪ wallets: d[c] = wallets[c] − need[c] (own currency first, FX-free — D-11).
2. b[c] = c === budget ? d[c] : convertCents(d[c], rate(c, budget)). If rate is null, c goes to `unconvertible`, is excluded from netting, and gets its own line if d[c] ≠ 0 (never fail the whole settlement — CONTEXT discretion).
3. net = Σ b[c]. net === 0n → direction null, no netted lines (D-13: exact zero only).
4. direction = net < 0 ? TOPUP : WITHDRAW. Same-sign currencies remain; opposite-sign currencies are consumed (D-15). Consume the opposite-side total from the same-sign lines in order: budget currency first, then currencies alphabetically. Fully consumed lines drop; a partially consumed line keeps remainder r (budget cents) and its own-currency amount = max(1, |convertCents(r, rate(budget, c))|) so a non-zero net never displays as 0. This floor is DISPLAY-ONLY: the task trigger and every total stay exact (D-13); `reserve-settle.ts` carries a comment saying so, and a golden test asserts the floored line's amount differs from the exact remainder only on display while `net` is unchanged.
5. equiv (D-16): for a line whose currency ≠ budget AND not in reserveWalletCurrencies → equiv = { budgetCurrency, cents: |remaining budget cents of that line| }. A line in the budget currency never has equiv.
6. Line order (UI-SPEC §6): currencies with a RESERVE wallet first, then the others; each group alphabetical.
