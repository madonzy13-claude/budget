New contracts (plan 11 consumes):

convertClosedMonthResult(input: {
  effLimitCents: bigint;            // month currency; the limit the engine judges this month against (cushion or normal, already resolved)
  noLimit: boolean;
  txs: Array<{ date: string; cents: bigint }>; // month currency, ordered (transaction_date, created_at, id); negatives = refunds
  closeRate: string;                // month ccy → current ccy, last rate available within the month
  rateOn: (date: string) => string; // month ccy → current ccy at a tx date
}): { limitCents: bigint; leftCents: bigint; overageCents: bigint } // all in CURRENT currency; limitCents = convertCents(effLimit, closeRate)

toEngineMonthEvents(r: { limitCents; leftCents; overageCents }, noLimit: boolean): { normalCents: bigint; cushionCents: bigint; spendCents: bigint; noLimit: boolean }
  normal = cushion = limitCents (the month's effective limit is already resolved, so both carry it);
  spend = overage > 0 ? limit + overage : limit − left;  noLimit passes through (spend = 0, limit = 0).
  Invariant: max(spend − limit, 0) == overageCents and max(limit − spend, 0) == leftCents.
</interfaces>

Overage attribution rule (fixed): walk txs in order keeping cumulative S (month currency) and a LIFO stack of above-limit portions {date, cents}. Positive tx: the part of it above max(L, S_before) is pushed with the tx date. Negative tx (refund): pops from the stack top first (reducing the most recent above-limit portion), the rest lowers S under the limit. Final Σ stack == max(S − L, 0). overageCents = Σ convertCents(portion, rateOn(portion.date)) (each portion rounded separately). leftCents = convertCents(max(L − S, 0), closeRate).
</context>
