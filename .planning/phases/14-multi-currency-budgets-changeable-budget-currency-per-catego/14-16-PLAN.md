<interfaces>
New repo method on CategoryLimitRepo: convertCurrentAndFutureSegments(tenantId, userId, categoryId, { fromCurrency, toCurrency, rate: string, currentMonthStart: string }): Promise<void>
  In one withTenantTx, under the same per-category advisory lock setLimit uses:
  - segment S covering currentMonthStart that started BEFORE it: close S at the day before currentMonthStart (effective_to) and insert a copy from currentMonthStart with every amount column (normal_amount, cushion_amount, needs_amount, wants_amount, legacy cushion_amount_cents) = convertCents(amount, rate) and normal_currency = cushion_currency = toCurrency; no_limit copied.
  - S starting exactly at currentMonthStart and every segment starting after it: UPDATE in place with converted amounts + toCurrency.
  - Segments ending before currentMonthStart: untouched.
New category-repo method: setCurrency(tenantId, userId, categoryId, currency).
Use case changeCategoryCurrency({ tenantId, userId, categoryId, currency }) → Result<{ category, limitsConverted: number }, Error>:
  same currency → ok no-op; rate = FX port rateAsOf(today from serverNow, budget tz) for fromCurrency→toCurrency, NoFxRateAvailable → err("fx_rate_unavailable"); then setCurrency + convertCurrentAndFutureSegments in the same tenant tx (or a single repo-level tx — keep atomic); after commit recomputeReserveTopupTask and the income-under-planned recompute (precedent: set-category-limit.ts).
Contract: changeCategoryCurrencySchema = z.object({ currency: z.enum(FIAT_CURRENCIES) }).
Route: PATCH /categories/:id/currency — same membership/permission gate as PATCH /categories/:id; 200 { category DTO incl. currency }, 404 foreign/missing id, 422 invalid currency or fx_rate_unavailable.
