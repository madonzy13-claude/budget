# 13.1-49 — Deposit opening entry on its start date (round-5 gap 1)

- `createHolding`: a deposit's opening `add` is dated `min(depositStartDate,
today)`; everything else keeps `openedOn ?? today`.
- Add sheet: the generic Date field is hidden for deposits and no `openedOn`
  is sent — the Start date is the only date.
- Migration 0091 (0089 safety pattern: NO FORCE RLS → temp fix table →
  owner-only backup `_investment_history_bak_0091` → UPDATE → FORCE RLS).

## Deviation (user-approved at the checkpoint)

The dry run found 1 deposit matching the planned rule (`add`, single entry)
and 10 more whose single entry is the 0088 migration's `start` kind — shown
as "Added money"/"Внесок" and dated the day 0088 ran (2026-07-12/13). The
user chose to move all 11, so 0091 matches `kind IN ('add','start')` with
backfilled entries included. Applied on dev: 11 rows backed up; all 15
deposits' entries now sit on their start date; FORCE RLS restored on both
tables. Past wealth snapshots are history and were not rebuilt.
