# Phase 13.1: Investments — assets with transactions - Context

**Gathered:** 2026-10-27
**Status:** Ready for planning

<domain>
## Phase Boundary

Investments become three levels for EVERY type: **L1 type group → L2 asset → L3 entries**.
An asset is a named group of entries (buys, sells, transfers, value updates, deposit interest)
within one type; the name is the grouping key. Each asset has **Swap** (Buy / Sell / Transfer)
and **Edit**. L3 entries are a fixed, date-ordered ledger that can only be deleted, newest-created
first. Selling out of investments can land the money in a budget wallet.

This replaces Phase 13's one-row-per-holding UI: the Sell sheet, the edit "What happened?" flow,
the History section inside Edit and the holding row actions are redesigned. Phase 13's booking
ledger (deltas + full undo), realized-gain math, contributions and Overview hybrid line carry over.

Why (Phase 13 UAT, 2026-10-27): a holding = one row can't model DCA. A user buys BTC many times,
holds it in one wallet, wants one line, and sells from the total.

</domain>

<decisions>
## Implementation Decisions

### Model

- **D-01:** 3 levels for all 11 types. Asset = entries grouped by **asset label (name) within a type**. Name is the key, not the instrument ("BTC Ledger" and "BTC Binance" are separate assets on the same price feed).
- **D-02:** Add form gets **name autocomplete** over existing assets of the type, **including hidden (quantity 0) assets**. Same name → the buy joins that asset; new name → a new asset.
- **D-03:** No tax support (no FIFO / PIT-38). A sell reduces **proportionally** from all of the asset's holdings at that date (average cost).
- **D-04:** Asset value/qty/cost are sums over its entries; P/L uses average cost. Asset has a **display currency** (render currency), separate from each entry's own transaction currency.

### Asset (L2) actions

- **D-05:** Swipe actions on an asset: **Swap · Edit**. No asset Delete button.
- **D-06:** **Edit** = change label and display currency only. Hand-valued assets (broker, savings, cash, and hand-priced quantity assets like a gold coin / custom crypto / collectibles) also get **current value** (or **current price** per unit). **No history in Edit** (the ledger lives in L3).
- **D-07:** Renaming to a label that already exists in that type → **blocked** (validation error).
- **D-08:** **Swap → Buy**: opens Add with type / name / instrument prefilled and locked.
  - Quantity types: quantity, buy price, buy currency, date.
  - Cash and savings: amount + currency + date; cost and value both rise by the amount (P/L unchanged).
  - **Broker: "Amount added" + "Account value after"** (prefilled = current value + amount, editable to what the broker app shows). One entry books the deposit (cost +amount, contributions +amount) AND refreshes market value, so the market move up to that day lands in P/L and the deposit never does.
- **D-09:** **Swap → Sell**: destinations as Phase 13 — New investment / Existing investment / Out of investments. "How much is left" locks the sold amount.
  - New/Existing with a **quantity** destination shows **buy price**: Existing → the destination asset's price, read-only, quantity derived; New → quantity and price both editable and linked (qty × price = sold amount).
  - Amount destination → one amount field.
  - A sale into New/Existing creates an entry in the destination asset (linked legs).
- **D-10:** **Swap → Transfer**: move part or all to another asset of the **same type** (same instrument checked **only for crypto and stocks**), or to a **new asset by giving a new label**. Transfer is not a sale (no realized, no contributions change); cost moves proportionally.
- **D-11:** **Deposit assets: Swap offers Sell only** (no Buy, no Transfer). One deposit per asset; a new deposit = a new asset.

### L3 entries (ledger)

- **D-12:** L3 lists **every entry**: Bought, Sold, Transfer in/out, Converted in/out, Value updated (hand-valued), Price updated (hand-priced qty), and deposit **Interest** rows. **Sorted by date, newest on top**; not sortable, **no DnD at L3**.
- **D-13:** Row = compact ledger line. Left: date · kind. Right: ±qty @ price and amount; sales add a small "realized +X". No per-entry live P/L.
- **D-14:** **Only entries are editable by deletion** — no editing of currency, amount, price or quantity. Delete is offered **only on the most recently CREATED entry** of the asset. Plain confirm dialog. Delete reverses exactly that entry's deltas (quantity, cost, value, realized, contributions) — the Phase 13 delta/undo model.
- **D-15:** A new entry's date must be **≥ the asset's latest entry date** (date picker min). Entries only append in time, so creation order = date order and a past sale's proportional split never changes.
- **D-16:** Linked legs (sale into another asset, transfer) are deletable **only when the entry is newest in BOTH assets**; delete removes both legs. Otherwise no delete on that row (row may explain why).
- **D-17:** Quantity reaches 0 → asset **hidden from the list**, history and realized kept, still offered in autocomplete; buying under that name revives it. **Deleting ALL its entries wipes the asset** including its history and realized gain.
- **D-18:** "Value updated" rows are deletable under D-14 (delete = back to the previous value).
- **D-19:** **Deposit interest rows**: auto-generated, one per passed capitalization date (at-maturity = one row at the end), **computed from rate + dates, never stored, read-only, skipped by the newest-first delete rule**. Interest is gain (P/L), not contribution. Phase 13 D-20 (part-sale restarts remainder from sale date, interest so far → realized) stays.

### Sell → wallet (Out of investments)

- **D-20:** Out of investments has an optional target: **existing wallet (any non-archived, incl. Possession) / new wallet / Nowhere**. Supersedes Phase 13 D-04 ("money does not flow into a wallet").
- **D-21:** Wallet balance changes as a **delta**: `current_balance += amount` on save; deleting the sale subtracts the same amount (even if the balance was edited since).
- **D-22:** Existing wallet → amount is in the **wallet's currency, locked**; prefilled = sold value at today's rate, editable.
- **D-23:** New wallet → inline name + wallet type + currency (prefilled with the source currency; switching currency converts the amount at today's rate; both editable). Its starting balance = the amount.
- **D-24:** Deleting a sale that created a wallet → the wallet stays, the amount is subtracted.
- **D-25:** No income row. It's a balance move only: investments fall, contributions fall by the received amount (Phase 13 D-02), budget income untouched.

### Look

- **D-26:** L1 type header keeps its chevron (expand/collapse, localStorage, as today). Fix Test 2: **no indent before the type name**; **value only by default**; the tap sum-up **mirrors the row**: line 1 = P/L % + P/L amount, grey caption = "unrealized · realized · share".
- **D-27:** **L2 has no chevron.** Tapping an asset row toggles both its stats (on the row's own background: P/L, avg price, qty, share — like today's tap-expand) and its L3 entries underneath. Assets start **collapsed**, open state remembered per device.
- **D-28:** **L3 is NOT indented**: same left edge as the asset, rendered as an "underground" strip like the spendings TO CONFIRM rows — darker background, muted text, inset top shadow on the first row (`inset 0 6px 8px -6px rgba(0,0,0,0.7)`, see `draft-row.tsx`).
- **D-29:** L2 row = today's holding row; the average price appears in the tap stats.

### DnD

- **D-30:** Same-level only. L1 reorders types (as today). L2 reorders assets within their type. L3 has no DnD. No moving between levels. Moving entries between assets happens only through Transfer.

### Carried in from Phase 13 UAT (tests 4–6)

- **D-31:** Sell sheet: "Sell everything" must look like an action, not a header. A **pre-submit sum-up above the submit button** shows what will happen (source reduced from → to; destination increased from → to, or created with X; wallet balance from → to). It replaces the "row after sale" preview. Amount received and its currency sit on **one line**.
- **D-32:** Phase 13 T6 bug ("edit quantity adds history but quantity unchanged", suspected CR-01 PATCH + /adjust race) is not hot-fixed: the flow is removed by D-06/D-14. Phase 13 code-review CR-01..04 get re-checked against the new model during planning (CR-03 negative/zero amounts and the BigInt/uuid 500s apply to the new endpoints too).

### Migration

- **D-33:** Existing holdings with the **same name + type merge into one asset**. Each holding's Phase 13 history entries (Start, Bought/Added, Sold, Withdrew, Converted…) become that asset's entries. Different names → separate assets.
- **D-34** (post-research, 2026-10-27): Same-name groups that **cannot merge cleanly** (mixed buy currency, mixed instrument, archived+active mix) are **NOT force-merged** — conflicting rows stay separate assets, renamed with a suffix (e.g. `BTC (2)`). User merges manually later via Transfer.
- **D-35** (post-research, 2026-10-27): Holdings with no ledger entries (active rows without buy price, archived rows) get a **backfilled Start entry with cost 0** so every asset has ≥1 entry. This is a TEMPORARY placeholder — user will later enter real cost for these. The migration must leave them findable (e.g. a marker/note on the backfilled entry) and a follow-up todo is recorded in STATE.md "Pending Todos".
- **D-36** (post-research, 2026-10-27): Edit currency on a hand-valued asset **converts the stored current value at today's FX rate**; transaction cost basis stays untouched in its original currency.
- **D-37** (post-research, 2026-10-27): A sale credited to a wallet (D-20) **fires the RESERVE + CUSHION task recomputes after commit**, same as a manual wallet balance edit.

### Phase 13 decisions — status

- **Kept:** D-02 (withdraw contributions), D-08 (Overview hybrid line), D-10/D-11 (stocks = equity + ETF, legacy mapping), D-13/D-14 (header per type with holdings; hidden when empty but realized counts), D-15/D-16 (header total P/L incl. realized, lifetime %), D-17 (amount received in destination currency), D-18 (realized frozen in budget currency at sale date), D-19 (contributions converted at each point's date), D-20 (deposit part-sale).
- **Superseded:** D-01 (row actions → Swap · Edit), D-03 (edit "What happened?" → Swap Buy/Sell + Edit current value), D-04 (no wallet → D-20 here), D-05 (History in Edit → L3 ledger), D-06 (delete any entry → newest-created only, no backdating before the latest entry), D-09 (Start entry → migration D-33), D-12 (holding reorder → asset reorder; L3 fixed).

### Claude's Discretion

- Amount vs quantity behaviour per type reuses today's `holdingShape` / `isQuantityHolding`.
- Hand-priced quantity assets record "Price updated" entries (as D-18).
- Schema shape (an assets table + entries vs evolving holdings + investment_history) is for research/planning, provided the D-14 delta-undo model holds.
- Swap UI form (menu vs segmented tabs), the Transfer form layout and the autocomplete component are UI-SPEC territory.
