# 13.1-18 — One FX rate per sale; sell-into = quantity × price (UAT 10, 11, 14)

**Realized now uses ONE deal rate — rate(source → received), the same lookup the form previews with — so a fair PLN→EUR swap books 0 even against the non-reciprocal 4.32 stored on dev. Sell-into a quantity destination is priced quantity × price (chosen for New, the asset's own for Existing); received follows, buy price is never received ÷ qty, and a tracked destination keeps its live current price.**

## Contract (consumed by 13.1-23)
- `receivedCents` is now OPTIONAL: required (else 422 `received_required`) only for Out and amount destinations; ignored for quantity destinations.
- New quantity destination: `holding.quantity` + `priceCents` (required → 422 `price_required`); `holding.currentPriceCents/currentPriceCurrency` may carry the instrument's live price (un-omitted from the schema) — stored as current price; without it current = chosen price.
- Existing quantity destination: `quantityBought` required (422 `quantity_required`); priced at the destination's own value ÷ qty; a client `priceCents` is stripped.
- `realizedInBudget({ receivedCents, sourceToReceivedRate, soldCostCents, sourceToBudgetRate })`.

## Deviations
- **Validation status 422, not 400.** This router's `invalid()` returns 422 for every Zod failure; tests follow the codebase convention. Non-numeric / ≤0 quantity and price → 422, never 500.
- **Live current price comes from the client**, not a server price port: create-holding has no price port either — it stores the client-sent `currentPriceCents` from instrument search. Same path reused.
- Tests that encoded the old model updated: two-rate `realizedInBudget` tests rewritten; "existing quantity destination derives the quantity from its price" replaced (qty is now required); delete-entry ×2 and list-entries ×1 now pass `quantityBought: "3"`.
