## Color

| Role            | Value                                                       | Usage                                                           |
| --------------- | ----------------------------------------------------------- | --------------------------------------------------------------- |
| Dominant (60%)  | `var(--canvas-dark)`                                        | Page, sheet backdrop                                            |
| Secondary (30%) | `var(--surface-card-dark)` / `var(--surface-elevated-dark)` | L1 header band, L2 rows, sheet fields, radio-cards, sum-up card |
| Underground     | `var(--surface-sunken-dark)` (flips in light theme)         | L3 strip background ONLY (same token as `draft-row.tsx`)        |
| Accent (10%)    | `var(--primary)`                                            | Reserved list below                                             |
| P/L ±           | `var(--trading-up)` / `var(--trading-down)`                 | TEXT only; neutral/zero `var(--muted-strong)`                   |
| Muted text      | `var(--muted-foreground)`                                   | L3 text (all of it except colored `realized` figure), captions  |
| Destructive     | `var(--destructive)`                                        | Entry-delete icon + confirm button text only                    |

Accent reserved for (exhaustive):

1. Primary submit in Swap sheet (Buy "Add to {name}", Sell "Record sale", Transfer "Move {…}") and in Edit ("Save changes").
2. Selected border of destination / wallet-target radio-cards, the pressed "Sell everything" / "Move everything" toggle buttons, and the active Swap segmented tab underline.
3. Drop indicator line while dragging a type block or an asset.
4. Focus ring on inputs (existing behaviour).

Rules:

- All colours via inline `style={{ color: "var(...)" }}` — tailwind-merge drops `text-[var()]` (see `investment-type-header.tsx`). Backgrounds via `style` too for L3 (`backgroundColor: "var(--surface-sunken-dark)"`). No hex anywhere; verify computed colour in light AND dark.
- Trading colours never as fills. Buy/Sell/Transfer are not green/red; sign (+/−) plus colour on the figure only.
- L3 text is muted, so the signed amount keeps muted colour (it is a ledger, not a P/L). Only the small `realized +X` sub-text on Sold rows is sign-coloured.

## Layout and Interaction

### 1. Three-level list (D-01, D-26..D-30)

```
L1 [grip][v] Crypto                  PLN 182,400       <- chevron kept
L2     [grip] BTC Ledger  PLN         PLN 90,200        <- no chevron
L2     [grip] BTC Binance             PLN 60,100
        (tap L2 -> stats on row bg, then L3 strip)
L3  ------ inset top shadow ------
    12 Oct · Bought        +0.0100 @ 64,000      640
    03 Oct · Sold          −0.0050 @ 66,000     −330   realized +45
    01 Oct · Transfer out  −0.0020                −130
```

**L1 header (D-26)** — fixes Phase 13 UAT test 2:

- Left padding: no indent before the type name. Layout left→right: grip (44px) · chevron (24px wide target 44 tall) · name. Remove any extra left margin/padding between chevron and name beyond `gap-2`; name starts directly after the chevron. Rows under the header start at the SAME left edge as the header content (no extra nesting `ml`).
- Default (not tapped): right column shows **value only** (`PLN 182,400`, 16/600). P/L figures not rendered by default.
- Tap on the right column toggles the sum-up, mirroring the L2 row stats:
  - line 1 (14/400, sign-coloured): `+24.1%  +35,420` (P/L % then P/L amount; % first)
  - line 2 (12/400 muted caption): `unrealized +29,100 · realized +6,320 · share 31.2%` — figures coloured by sign, words muted. Wraps on 360px (`break-words`, `min-w-0`); never truncates.
- The old always-on "incl. realized" sub-line and the `dl` split grid are REMOVED (replaced by line 2). Header min-height 56px default, grows when tapped.
- Chevron expand/collapse unchanged (localStorage, `aria-expanded`).

**L2 asset row (D-27, D-29)**

- Today's holding row (type icon via `holdingIcon`, name, currency, value, grip). **No chevron.** Whole row (except grip and amount cell when inline-editable) is the tap target, `role="button"`, `aria-expanded`.
- Tap toggles BOTH: (a) stats on the row's own background (existing pattern): line 1 `P/L % + P/L amount`, caption `Avg price {p} · Qty {q} · Share {s}%` (avg price new, D-29; qty omitted for amount-shaped types per existing `showQty` rule); (b) the L3 strip directly underneath. Collapsed by default. Open set persisted per device in localStorage key `inv.assetOpen.v1` (array of asset ids), seeded into `bdpStore.wallets.expandedRows`.
- Desktop: row click still toggles (Phase 13 desktop edit-on-click is removed; Edit is a hover icon button + swipe-equivalent actions: Swap, Edit, 44px).
- Swipe-left reveals **Swap · Edit** only (D-05). Order: Swap (`ArrowRightLeft`, `--surface-elevated-dark` bg, `--body-on-dark` icon) · Edit (`Pencil`). No Delete, no Sell. Keep `touch-pan-x`, grip/swipe separation.
- Assets with quantity 0 are not rendered (D-17).

**L3 ledger strip (D-12..D-16, D-28)**

- Container: no left indent (same left edge as L2 content), `backgroundColor: var(--surface-sunken-dark)`, `color: var(--muted-foreground)`. First row gets `boxShadow: "inset 0 6px 8px -6px rgba(0,0,0,0.7)"` (as `draft-row.tsx` `topShadow`). Full row width; no border radius; hairline `var(--hairline-dark)` between rows.
- Order: date desc, ties by creation desc. Not sortable, no grip, no DnD, not focusable by dnd-kit. Rows are `role="row"`, `data-ledger-row`, `tabIndex={-1}`.
- Row grid (min-h 40px, `px-2 py-1`, `gap-2`):
  - Left (min-w-0): line 1 date (12/400, `Intl` short date, one call so uk/pl genitive month is right) · kind label (12/400). Optional line 2 for linked legs: `Link2` icon 12px + counterparty (`to BTC Binance`) 12/400, truncate.
  - Right (shrink-0, text-right, BinancePlex): line 1 `±qty @ price` (12/400) for quantity entries / blank for amount entries; line 2 amount 14/400 signed (`+640`, `−330`) in the ASSET display currency. Sold rows add `realized +45` (12/400, sign-coloured) as line 3 right-aligned.
  - No per-entry live P/L (D-13).
- Kinds (EN): Bought, Sold, Transfer in, Transfer out, Converted in, Converted out, Added money, Value updated, Price updated, Interest. "Converted" = a sale into another asset (D-09 linked legs); "Transfer" = D-10.
- **Interest rows (D-19):** read-only, kind "Interest", amount `+X` in muted text, caption "Auto-calculated" (12/400) in place of line 2 icon. Never show delete, even when newest. They render in date order amongst real entries; the "newest created" delete rule skips them.
- **Delete (D-14, D-16):** only ONE row per asset can show delete: the most recently CREATED non-interest entry. Mechanics (mirror draft-row reveal): tap the row to reveal a trailing 44x44 `Trash2` icon button (`--destructive` colour via inline style, `aria-label` "Delete {kind} from {date}"); desktop also on hover. Tapping opens AlertDialog. All other rows: tap does nothing visible (no reveal).
  - Linked leg whose counterpart is not also newest in its asset: no delete; row shows a muted 12px line `Remove the later entries in {other asset} first.` only once the row is tapped.
  - Row for a single-leg entry that is not the newest: tapped → muted 12px helper `Only the latest entry can be deleted.`
- Empty L3: cannot occur (an asset with zero entries is wiped, D-17).
- Loading: 3 `Skeleton` rows (existing `wallets-skeleton`) on the sunken bg while an asset's entries fetch (lazy on first open).

**DnD (D-30):** L1 blocks and L2 within type keep the Phase 13 flat-sortable rules (Space guard needs `roledescription` AND body marker). L2 sortable items are constrained to own type; L3 outside any SortableContext. Collapse open L3 strips while an L2 drag is active (stable targets); restore on drop.

### 2. Swap sheet (D-08..D-11, D-31)

One `Sheet` (same shell/width/sticky footer as `holding-sheet.tsx`). Title: `Swap {asset name}` (16/600). Directly under the title, `SegmentedToggle` with three tabs **Buy · Sell · Transfer** (each min 44px tall, `role="radiogroup"`, arrow keys). Default tab: Buy. **Deposit assets (D-11): no tabs; title `Sell {name}`; only the Sell form.** Switching tabs keeps entered date, resets the rest; no confirm. Footer is sticky, wraps, contains (top to bottom): sum-up card · primary button (full width) · secondary "Discard" (text button, 44px).

Footer must wrap on 360px in PL/UK: buttons full width stacked (never side-by-side), labels `break-words`, no `truncate`, no fixed heights.

**Date (all tabs):** native-style date input as other forms; `min` = asset's latest entry date (D-15), `max` = today. Helper when min > today-limited: `Not before {date} — the latest entry on this asset.`

#### 2a. Buy tab (D-08)

Locked, read-only prefilled fields at top (Lock icon, muted bg): Type · Name · Instrument (the same row look as disabled inputs in `holding-sheet`). Then by shape:

- **Quantity types:** Quantity · Buy price (per unit) · Buy currency (`CurrencyPicker`) · Date. Live helper line: `Total {qty × price} {ccy}`.
- **Cash / savings:** Amount · Currency · Date. Helper: `Cost and value both go up by this amount. P/L doesn't change.`
- **Broker:** Amount added (+ currency chip = asset currency) · Account value after (prefilled = current value + amount, editable, helper `Was {current} + {amount}. Set it to what your broker app shows.`) · Date. Live split line beneath (12/400): `P/L {+3,250} from market move · {+0} from deposit` — figures sign-coloured. Editing "Amount added" re-prefills "value after" only while the user hasn't edited it (track `valueAfterTouched`).
  Footer sum-up (see 2d). Primary: `Add to {name}`.

#### 2b. Sell tab (D-09, D-20..D-23, D-31)

Section order (stacked, not a wizard):

1. **How much is left?** — quantity types: "Quantity left" + helper `You hold {qty}`; amount types: "Value left" + helper `Current value {value}`. **"Sell everything" becomes an outlined secondary Button (`variant="outline"`, 44px, label "Sell everything", `ArrowRightLeft` NOT used) placed to the right of the field label row, not plain text** (fixes UAT test 4). Pressed state: button gets selected border (yellow) + check icon and the input is set to 0 and read-only; pressing again clears. Validation 0 ≤ left < held.
2. **Where did the money go?** — three radio-cards (New investment / Existing investment / Out of investments), as Phase 13.
3. **Destination detail:**
   - New: type picker + type-specific fields (name via `asset-name-combobox`, instrument search). For quantity destination: **Quantity** and **Buy price** side by side stacked on 360px, linked: editing one derives the other so qty × price = sold amount (last-edited field wins; the other is derived and shown with a small `Linked` caption).
   - Existing: searchable select of OTHER assets (grouped by type). Quantity destination: Buy price **read-only** = destination asset price (Lock icon), Quantity derived read-only. Amount destination: no extra field.
   - Out: wallet target block (below).
4. **Amount received + currency on ONE line** (UAT test 5 fix): a single flex row `[ amount input (flex-1, min-w-0) ][ currency chip/picker (shrink-0, 96px) ]`; never wraps below 360px. Currency: destination currency (New/Existing, locked) or, for Out with a wallet, the wallet currency (locked) / for Nowhere the source currency switchable. Helper `Prefilled from today's value. Change it to what actually landed.`
5. **Date.**

**Out of investments — wallet target (D-20..D-25):** after choosing Out, show a second radio group "Where should the money go?" with three radio-cards: **Existing wallet / New wallet / Nowhere** (default Nowhere to preserve Phase 13 behaviour).

- Existing wallet: `Select` of non-archived wallets incl. Possession (name + currency + current balance, grouped by wallet type). Amount currency locked to the wallet currency; prefilled with sold value at today's rate, editable. Helper `Added to the wallet balance. Not counted as income.`
- New wallet: inline stack: Name (required) · Wallet type (`Select`: Spendings / Cushion / Reserve / Possession / Other, labels from existing wallet i18n) · Currency (`CurrencyPicker`, prefilled with source currency). Changing currency converts the amount at today's rate (both stay editable); starting balance = amount. Helper `The wallet starts with this amount.`
- Nowhere: no extra fields.

#### 2c. Transfer tab (D-10)

Not a sale. Fields:

1. **Move** — "Quantity to move" (quantity types) or "Amount to move" (amount types), helper `You hold {x}`; outlined "Move everything" button (same pattern as Sell everything). Partial or all.
2. **To** — two radio-cards: **Existing asset** / **New asset**.
   - Existing: `Select` of other assets of the SAME type; for crypto and stocks additionally filtered to the same instrument (helper `Same instrument only.`); other types show all same-type assets. If none: empty hint (see copy) and the segmented option for New remains.
   - New asset: `asset-name-combobox` ("New asset name"); blocked with inline error if the label exists in the type (D-07 logic reused: `That name is already used. Pick it from Existing asset.`).
3. Date.
   Info line (12/400 muted, `Info` icon): `Not a sale: no realized gain, cost moves with it.`
   Primary: `Move to {target}` (falls back `Move asset` until a target is chosen; disabled until valid).

#### 2d. Sum-up card above submit (D-31) — replaces "Row after sale"

`surface-card-dark` card, md padding, rendered above the primary button on every tab; title 16/600 `What will happen`; lines 14/400, each `label  before → after` with the AFTER figure BinancePlex 16/600 (the 24/600 display figure is used only when the card has exactly one resulting figure (that line's "after"); otherwise every "after" is 16/600). Lines by case:

| Tab / case          | Lines                                                                                                                             |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Buy (quantity)      | `{name}: {qty0} → {qty1}`, `Value {v0} → {v1}`                                                                                    |
| Buy (cash/savings)  | `{name}: {v0} → {v1}`, `P/L unchanged`                                                                                            |
| Buy (broker)        | `{name}: {v0} → {v1}`, split line from 2a                                                                                         |
| Sell, New           | `{name}: {v0} → {v1}` (or `gone from your list` when left = 0), `New asset {dest} created with {x}`, `Realized {+/-r}` (coloured) |
| Sell, Existing      | `{name}: {v0} → {v1}`, `{dest}: {d0} → {d1}`, `Realized`                                                                          |
| Sell, Out / wallet  | `{name}: {v0} → {v1}`, `{wallet}: {b0} → {b1}` or `New wallet {w} starts with {x}` , `Realized`                                   |
| Sell, Out / Nowhere | `{name}: {v0} → {v1}`, `Leaves your investments`, `Realized`                                                                      |
| Transfer, Existing  | `{name}: {v0} → {v1}`, `{target}: {t0} → {t1}`, `Realized unchanged`                                                              |
| Transfer, New       | `{name}: {v0} → {v1}`, `New asset {target} created with {x}`                                                                      |

Preview is display-only Number math (server is authoritative, books in BigInt). While invalid inputs: card shows muted `Fill in the fields above to see what will happen.` Amounts across currencies show each line in its own currency.

States: loading submit (spinner label `Saving…`, button disabled), FX unavailable (error under amount, submit disabled), iOS keyboard open (footer stays above keyboard, reuse `holding-sheet` viewport logic; sum-up card collapses to one line `Realized {x}` while an input is focused only if footer > 40% viewport height — otherwise unchanged).

Success: close sheet; toast `Sale recorded` / `Added to {name}` / `Moved to {target}`; invalidate investments, type-summary, history/entries, overview, and **wallets** when a wallet was touched. Failure: rollback toast (offline-write rules, no queue).

### 3. Add form (D-02)

`holding-sheet.tsx` Add flow: "Name" field becomes `asset-name-combobox`.

- Popover + `Command` list under the input, filtered by typed text, scoped to the chosen TYPE. Includes hidden (qty 0) assets, marked with muted `Closed` badge (12/400).
- Selecting an existing name: sheet shows muted note `This joins {name} (currently {value}).` (hidden: `This reopens {name}.`); instrument/type fields lock to that asset's.
- Typing a new name: last item `Create "{typed}"` (always first match for exact-miss). No note.
- Keyboard: ArrowUp/Down, Enter selects, Esc closes popover (not sheet). `aria-autocomplete="list"`, `role="combobox"`. Max 6 visible items then scroll.
- Name uniqueness is case-insensitive trimmed within the type.

### 4. Edit sheet (D-06, D-07)

Fields: Label (name) · Display currency (`CurrencyPicker`). Plus, for hand-valued assets (broker, savings, cash): **Current value**; for hand-priced quantity assets (gold coin, custom crypto, collectibles): **Current price per unit** (unit label). Saving a changed value/price books a "Value updated" / "Price updated" entry (appears in L3). No History section, no "What happened?", no Type/Quantity fields, no Delete.
Rename collision: inline error under Label `This type already has an asset with that name.`, submit disabled. Helper under Display currency: `Only changes how this asset is shown. Entries keep their own currency.`
Footer: primary `Save changes`, secondary `Discard`. Success toast `Saved`.

### 5. Delete entry (D-14, D-16, D-17, D-18)

AlertDialog, destructive confirm, no typed confirm. Copy by case in Copywriting. If the delete will remove the LAST entry of an asset, body adds the wipe warning (D-17). Linked legs: copy states both sides are removed (D-16).

### 6. Migration visibility (D-33)

No UI. After migration merged assets simply appear as one L2 row with a long L3 (Start/Added/Sold… history mapped to kinds above). "Start" maps to **Bought** (qty types) or **Added money** (amount types); no "Start/Automatic" tag remains.

## Accessibility and Platform

- Segmented Buy/Sell/Transfer: `role="radiogroup"`; destination and wallet-target cards `role="radio"`, arrow-key navigation, selected conveyed by border + check icon, not colour alone.
- L2 row `aria-expanded` on the tappable row; ledger container `role="rowgroup"` labelled `{name} entries`. Delete button `aria-label` = `ledger.deleteAria`.
- Signs in text (+/−, real minus U+2212) and not colour alone. Locked fields have `readOnly` + `aria-readonly` + Lock icon.
- Combobox follows ARIA 1.2 pattern; Esc closes popover only.
- 360px: gutters 16px, no horizontal scroll in EN/PL/UK; every footer, caption and card text uses `break-words min-w-0`; nothing in 13.1 uses `truncate` except the counterparty name on an L3 line 2 (still has full text in `title`/aria). Verify at 360px for all three locales with the longest strings (UK).
- iOS: `touch-pan-x` on swipe; Radix `onCloseAutoFocus` preventDefault; date input `min` uses ISO; one `Intl.DateTimeFormat` call for day+month (genitive in uk/pl), `hourCycle: "h23"` if any time shown.
- Light theme: L3 bg via `--surface-sunken-dark` (flips to light); inset shadow stays the draft-row value (works on both). Check computed colours.
- Test hooks: testids `asset-row-{id}`, `asset-ledger-{id}`, `ledger-row-{entryId}`, `ledger-delete-{entryId}`, `swap-tab-{buy|sell|transfer}`, `swap-summary`, `asset-name-option-{n}`, `wallet-target-{existing|new|nowhere}`; keep `investment-group-*` ids on L1.

## Assumptions to confirm

1. **Swap UI = one sheet with segmented Buy · Sell · Transfer tabs** (not a menu); default tab Buy; deposits skip the tabs and open Sell directly.
2. **L3 delete reveal** = tap the newest row, then a trailing Trash2 appears (draft-row pattern); no swipe at L3.
3. **Wallet target default for Out = Nowhere**, preserving Phase 13 behaviour when the user ignores the new block.
4. **"Sell everything" = outlined toggle button** that locks left = 0; second press clears.
5. **Interest rows** show amount in muted text with "Auto-calculated" caption; never selectable.
6. **Closed (qty 0) assets in autocomplete** carry a "Closed" badge and reopen on buy.
7. **L1 line 1 order** = `P/L % then P/L amount` per the user-approved sketch (`+24.1%  +35,420`); the caption order `unrealized · realized · share`.
8. **Linked leg delete blocked copy** appears only on row tap, not permanently, to keep the strip quiet.
9. **Sum-up display figure (24/600)** is used only when the card has exactly one resulting figure; otherwise all "after" figures are 16/600.
10. **Start entries from migration** are labelled by what they are (Bought / Added money), no "Automatic" tag.
11. **Open-state storage** `inv.assetOpen.v1` localStorage, per device (D-27), alongside the existing group-collapse key.
