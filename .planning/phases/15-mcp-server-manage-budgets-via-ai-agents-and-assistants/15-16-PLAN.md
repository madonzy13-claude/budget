<objective>
The import flow: server-side check for all five D-14 kinds, a single user Q&A on problems, all-or-nothing commit, and undo. This plan builds the preview for every kind, and the commit/rollback/undo machinery end to end for transactions (+ categories created from category_map). Plan 15-20 adds commit + rollback + undo for category_limits, investment_entries, wallet_balances and scheduled_payments on the same KIND_COMMIT table (split for context cost, not scope).

Purpose: MCP-07 (D-13..D-18). No parsers: the agent normalises any format to strict JSON. Atomicity is compensating (RESEARCH Open Question 2, RESOLVED): every use case opens its own tx, so a failure triggers `undoCallOrBatch(..., { mode: "rollback" })` from 15-15.
Output: import.ts + tests.
</objective>
