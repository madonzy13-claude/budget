  </read_first>
  <action>Present both questions with the options below in one message and wait. Record the answer in 15-01-SUMMARY.md under "Decisions" as `investment_undo: a1|a2` and `wallet_history: b1|b2`.</action>
  <decision>(a) What can the agent's `undo` tool revert for investment writes (D-11)? (b) D-14 lists "wallet balance history" as importable, but the app stores only each wallet's CURRENT balance; the only dated store is the per-budget wealth snapshot (sum of all wallets + investments). What should a dated wallet-balance import do?</decision>
  <context>(a) D-09: investment entries delete newest-first only, and deleting a sell/transfer reverses its wallet effect. So undoing an agent-recorded buy/sell/transfer is the app's own "delete entry" while it is still the newest. Undoing an agent's entry DELETE would need new re-create semantics. (b) There is no write path for past wallet balances. Writing past wealth snapshots touches the Overview growth chart baseline (see the project memories on the growth baseline and the broker monthly rebuild).</context>
  <options>
    <option id="a1">
      <name>(a) Undo agent-created entries via the existing newest-first delete (recommended)</name>
      <pros>Fixes the common mistake (wrong buy/sell) with zero new domain logic: DELETE /budgets/:id/investments/entries/:entryId. update_holding_value is undone by PATCH back to before.</pros>
      <cons>Skipped and reported when the entry is no longer the newest or was edited since. An entry DELETE is not undoable.</cons>
    </option>
    <option id="a2">
      <name>(a) No undo for investment writes except asset create (research default)</name>
      <pros>Smallest surface.</pros>
      <cons>The agent cannot fix its own wrong buy/sell.</cons>
    </option>
    <option id="b1">
      <name>(b) Newest row per wallet sets the current balance (set-wallet-balance); older rows are reported in import_preview as "the app keeps no per-wallet history" (recommended)</name>
      <pros>No new data model. Honest to the agent and the user. Reuses D-10 behaviour.</pros>
      <cons>Past wallet balances are not kept anywhere.</cons>
    </option>
    <option id="b2">
      <name>(b) Also write month-end wealth snapshots from the summed history</name>
      <pros>Old balances show up in the Overview growth/capitalization chart.</pros>
      <cons>A new write path into budget_wealth_snapshots. The agent must supply every wallet per date or the sum is wrong. Interacts with the growth-baseline rules. Needs its own plan (the planner adds a gap plan; 15-16 implements only b1's part).</cons>
    </option>
  </options>
  <acceptance_criteria>
    - Both chosen option ids are recorded in 15-01-SUMMARY.md under "Decisions". Plans 15-14, 15-15 and 15-16 read them.
