# Overview perf round 2: CPU and duplicated reserve replays

After 261102-pf1 the database side was cheap; what was left was CPU.

1. One Overview page load replays the reserve engine ~6 times (cards, planned,
   overspent, reserve-fit, projection, reserves), ~50ms each; /budgets/aggregate
   once per budget → `cacheReservePositions`: GETs share one replay (10s TTL),
   every non-GET request invalidates, writes and the worker always replay fresh.
2. Deposit value: big.js exact `pow(n)` (digits explode) + temporal-polyfill
   date math → squaring rounded at 40dp + epoch-day math, identical cents.
3. Reserve fit: bisection re-walked invariant month data per candidate →
   hoisted + memoised per reserve amount, identical output (golden hash).
4. pg tracing `operationOf` trimmed/split whole statements → anchored regex.
5. The 10 failing tests: demo manifest missing 6 recent columns; DEMO_* host
   env leaking into demo-suppression / demo-guard; two date-dependent planned
   tests (clock not pinned, horizon rule changed in be7a6bfe).
